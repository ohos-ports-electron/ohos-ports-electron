# Reproduction and release conditions

Original input and ordered package patches are in inputs.lock.json. Package identity, version, content inventory and frozen SHA256 must match on every build. Package replay is deterministic; the optional launcher is compiled separately for the demos and is not part of candidate.tgz. No addon ABI or precompiled .node is introduced.

The same 34-case device plan checks real installed bytes, default/specified browser token receipts, files, named apps, unsupported options and errors, ChildProcess identity/lifetime, exact executable argv, wait/exit/kill/fallback, cross-Ability parameters and cooperative results, long waits/concurrency/timeouts, and a real Worker child process. Every required candidate target must pass twice with different fresh PIDs/runIds. Baseline failures retain their actual results. Host tests simulate the platform and Ability replies and are reported separately.

Demos use --jitless. Electron 25 sets it before native V8 startup and omits unavailable legacy code-memory permissions. 34/40 retain all vendor framework modules and use locally isolated official API declarations required by those frameworks. Electron 40 Worker child-process exit delivery uses the separately maintained engine-hash-guarded `electron40-child-reaper-3afb8387` helper. It polls the exact vendor engine's real child-wait function and does not fabricate exit status. The helper is a host runtime condition, never an npm library patch. Exact sources, hashes and license are archived with device evidence. Synchronous spawn, generic standalone Node 18, all browser privacy protocols, arbitrary app-process-exit waiting and full upstream coverage are outside the claim.

A consuming HAP must integrate the shipped OpenHostBridge, optional signed private HNP, and the same application-private bridge directory. Cooperative target applications must understand Want parameters and return AbilityResult themselves. Parameter and lifecycle restrictions are documented in PACKAGE_README.md. Complete on-device npm CLI installation is not claimed; normal host npm installation with real dependencies and device execution of those installed bytes are verified separately.

The GitHub workflow builds one candidate, binds it to the checkout SHA and current recipe, checks recorded device evidence, and runs host protocol regressions using the exact Node versions observed on-device. The Node 18.15 role executes upstream Electron 25.3.2 RUN_AS_NODE with its newer V8; it does not claim stock Node 18 support. Only a trusted main push may enter the npm-publish environment. PR, fork, other branch, local default invocation and workflow_dispatch cannot upload.

Trusted Publisher configuration: package @ohos-ports-electron/open; GitHub owner ohos-ports-electron; repository ohos-ports-electron; workflow open-electron-oh.yml; environment npm-publish. Allow direct npm publish and independent npm dist-tag permissions. Use hosted runners and supported npm/Node versions. Bootstrap or 2FA authentication, if needed, is handled interactively after the complete device evidence and PR checks are available. Successful same-byte skip proves package verification, not a fresh OIDC upload.

Active channel is beta, required tags latest and beta. Never create or update legacy electron-oh; keep version suffix -electron-oh.0. Refuse to overwrite an existing version with different bytes, and refuse to roll a tag back from a different newer release. New upload and already-published paths both verify registry bytes and tags. The Pages workflow refreshes public registry data after a successful trusted publication and uses beta_version and @beta installation.
